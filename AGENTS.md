# AGENTS.md

Cross-tool instructions for AI coding agents working in this repository.
This is the **tool-agnostic** source of truth — read by Codex, Copilot, Cursor,
Windsurf, Aider, Zed, and others, and also by Claude Code. Tool-specific files
(e.g. `CLAUDE.md`) import or extend this file rather than duplicating it.

## Project overview

This repository holds an iOS capture app, a Python pipeline and (later) a browser
viewer for recording a building while it is under construction, so the structure
and services hidden by finished surfaces stay findable afterwards.

A LiDAR iPhone records, per room and per construction phase, posed colour frames,
LiDAR depth with per-pixel confidence, high-resolution stills, tapped room
landmarks and printed-marker sightings. A pipeline on the owner's PC validates
each session, solves marker poses, aligns sessions to the architectural floor
plans and, later, builds meshes, splats and AI labels. A viewer then puts all of
it on the plan, phase by phase.

**Read `docs/plan.md` first**, then `docs/implementation-guide.md`. The product is
named VividHome ([ADR-0024](docs/adr/0024-name-vividhome.md)).

## Repository layout

```
docs/        plan, feasibility, design docs, ADRs, UI brief, schedule, protocols, format spec
ios/         Swift: the SwiftUI + ARKit app, plus a pure-Swift core package tested on Linux
pipeline/    Python 3.12 package managed with uv: validate, markers, plan, align, inspect
samples/     one trimmed real capture session used as a test fixture
web/         browser viewer (later)
```

## Setup, build and test

There is **no manifest at the repository root**, so the usual root auto-detection
finds nothing. Each stack is driven from its own directory.

- **Python pipeline** (`pipeline/pyproject.toml`, uv-managed):
  `uv sync --project pipeline`, then `uv run --project pipeline ruff check pipeline`
  and `uv run --project pipeline pytest pipeline -q`.
- **Swift core** (`ios/VividHomeCore`):
  `swift test --package-path ios/VividHomeCore`. Pure Foundation, no ARKit or simd, so it
  builds and tests on Linux.
- **iOS app**: cannot be built here. There is no Mac and no Xcode in the agent
  environment. The Xcode project is generated by XcodeGen **on the CI runner** from
  `ios/project.yml`; it is not committed.

`.harness.yml` records the deviations from the shared harness defaults, including
the one-line local gate: `cd pipeline && uv run ruff check . && uv run pytest -q`.

## Conventions

- **Commits:** imperative subject ("Add X", not "Added X"), kept short; explain the
  why in the body when it isn't obvious. Conventional Commit prefixes are welcome
  but not required.
- **Branching:** never commit directly to the default branch; use a feature branch
  and open a PR.
- **Before pushing:** run the gates for the stack you touched and make sure they
  pass. Match the surrounding style rather than introducing new patterns.
- **Scope:** keep changes focused on the request; unrelated refactors belong in
  their own PR.

## Rules specific to this project

1. **The iOS layer compiles only in CI.** Push, then read the job log through the
   GitHub API and fix what it actually reports. Never guess at a Swift compiler
   error, and never claim an iOS change builds.
2. **`docs/session-format.md` is a contract** between the app and the pipeline. Any
   change to units, axes, matrix order, file encodings or file names requires a
   `format_version` decision and updates on both sides. Additive optional fields
   keep version 1; readers must ignore unknown fields. It is also the **only**
   cross-language contract: clients are independent implementations of it, never
   consumers of a shared library, and a new client (Android, web) joins by adding
   an arm to the `contract` CI job (ADR-0021).
3. **Keep logic out of the ARKit layer.** Anything testable belongs in the
   pure-Swift core package so Linux CI can cover it. The ARKit layer stays thin and
   follows Apple's documented patterns.
4. **No third-party Swift dependencies, and no embedded frameworks.** The TestFlight
   flow archives unsigned and signs on export, which only re-signs what the archive
   signed, so an embedded framework breaks it.
5. **Swift 5 language mode.** Strict concurrency cannot be iterated on locally here.
6. **Raw capture sessions are immutable.** The pipeline reads them and writes derived
   data beside them under `derived/`.
7. **Architectural decisions get an ADR** under `docs/adr/`. An accepted ADR is never
   edited to change its decision; write a new one that supersedes it.
8. **Keep `docs/status.md` true.** It records what is built, what only compiles,
   and what is blocked. Update it in the commit that changes the answer, not
   afterwards. "Compiles" and "works" are different claims and the file keeps
   them apart on purpose.
9. **AI output is a candidate, not a fact.** Anything a model infers about a building
   is stored with its source and confidence and stays unconfirmed until a human
   confirms it. Never present a code-compliance conclusion as authoritative.

## Security

- Never commit secrets. `gitleaks` runs in `pre-commit` as a backstop, and the
  App Store Connect key lives only in GitHub Actions secrets.
- This repository is public for now. Workflows that run with write permissions must
  gate on author association; see the comment in `.github/workflows/claude.yml`.
- Don't weaken TLS verification or disable security tooling to make something pass;
  fix the underlying issue instead.
