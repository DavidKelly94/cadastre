# iOS app design (Cadastre)

Native Swift/SwiftUI app with a thin ARKit layer. Everything that can be pure logic lives in the `CadastreCore` package so it is unit-tested on Linux; the ARKit layer follows Apple's documented patterns and stays small because it can only be tested on a phone via TestFlight.

Targets: iOS 17.0+, LiDAR required, portrait only, Swift 5 language mode, no third-party dependencies.

## 2. Screens and navigation

`NavigationStack` rooted at `ProjectPickerView`. First launch shows `OnboardingView` as a full-screen cover until the LiDAR check and camera permission pass.

| Screen | Purpose | Primary action | Notes |
|---|---|---|---|
| Onboarding | LiDAR/ARKit capability check, camera permission, 3-card protocol tutorial | Continue | Blocks on unsupported device with a clear message |
| ProjectPicker | list projects; create one (name → slug) | Open / New project | Also links to Markers, Settings, Test plan |
| RoomPicker | choose level and room (typed once, reused), **phases as multi-select chips** defaulting to the room's last pass, notes, expected marker IDs | Start capture | Persists last choices |
| Capture | full-screen `ARView` with HUD and buttons | REC / Stop | See section 3 |
| SessionReview | stats, top-down trajectory sketch, thumbnails strip, stills, markers, landmarks, quality flags, notes | Open in Files, Share zip, Delete | "Open in Files" uses `shareddocuments://` + the session path |
| Markers | list of marker IDs with placement notes and seen-in-N-sessions | Add note | Print instructions link to `docs/markers.md` |
| Settings | keyframe thresholds, JPEG quality, 30/60 fps, marker physical width, diagnostics | — | `@AppStorage` |
| TestPlan | per-build checklist | — | Markdown rendered with `AttributedString(markdown:)` per paragraph |

## 3. Capture screen

```
┌────────────────────────────────────────┐
│ ● normal  03:12  kf 412  drop 0  9.8GB │  status strip (tracking colour, elapsed, keyframes, dropped, free space)
│ thermal fair   markers: CD-012 CD-013  │
│                                        │
│              camera + mesh             │
│                                        │
│ [N wall] [E wall] [S wall] [W wall]    │  coverage chips (tap to tick)
│ [ceiling] [floor] [close-ups]          │
│                                        │
│  Kitchen · electrical                  │
│ (mesh) (landmark)   [ ● REC ]  (still) │  bottom bar, thumb reach
└────────────────────────────────────────┘
```

Behaviour:
- Entering the screen runs the AR session immediately (preview, not recording). REC starts a session directory and the recorder; Stop finalizes (mesh export, manifest) with a progress overlay, then navigates to SessionReview.
- `Still` calls `captureHighResolutionFrame`; at most one call per second; haptic on success.
- `Landmark` shows a label picker (corner-nw/ne/se/sw, door-…, window-…, floor, other) then waits for a tap on the screen; the tap is raycast to a world point and logged; a small sphere marks it in the view.
- `Mesh` toggles `arView.debugOptions.showSceneUnderstanding`.
- The status strip colour follows tracking state: green normal, amber limited (with the reason text), red not available.
- Interruptions (`sessionWasInterrupted`) pause recording and show a banner; on `sessionInterruptionEnded` recording resumes in the same session (poses stay in the same frame only if ARKit relocalizes; if `trackingState` reports `relocalizing` for more than 10 s, prompt the owner to stop and start a new session).

## 4. ARKit configuration (`ARSessionController`)

```swift
let config = ARWorldTrackingConfiguration()
config.worldAlignment = .gravity
config.frameSemantics = [.sceneDepth]                // raw depth + confidence
config.sceneReconstruction = .meshWithClassification
config.environmentTexturing = .none
config.planeDetection = []                            // estimatedPlane raycasts still work; keep it cheap
config.isAutoFocusEnabled = true
if let fmt = ARWorldTrackingConfiguration.supportedVideoFormats
    .first(where: { $0.imageResolution.width == 1920 && $0.framesPerSecond == 30 }) {
    config.videoFormat = fmt                          // 30 fps for thermal headroom; Settings may pick 60
}
config.detectionImages = markerImages                 // Set<ARReferenceImage>, physicalWidth 0.20 m
config.maximumNumberOfTrackedImages = 4
config.automaticImageScaleEstimationEnabled = false   // we trust the printed size
```

Guards before running: `ARWorldTrackingConfiguration.isSupported`, `supportsFrameSemantics(.sceneDepth)`, `supportsSceneReconstruction(.meshWithClassification)`. Any false → Onboarding shows "This app needs an iPhone Pro with LiDAR".

Reference images: built once at launch from `Resources/Markers/*.png` with `ARReferenceImage(cgImage, orientation: .up, physicalWidth: settings.markerWidth)`; `name` = `CD-017`. Call `validate(completionHandler:)` on each and log failures (a marker that fails validation is still usable offline via AprilTag).

The controller is the single `ARSessionDelegate` and fans out `didUpdate frame`, `didAdd/didUpdate anchors`, interruption callbacks to the recorder, marker logger and HUD state.

## 5. Recording pipeline

```
ARSessionDelegate.session(_:didUpdate:)        (main thread, 30 or 60 Hz)
   │
   ├─ HUD state update (tracking, thermal, elapsed)            cheap, every frame
   │
   └─ if recording:
        KeyframePolicy.shouldKeep(pose, time, tracking)         CadastreCore, pure
          │ yes
          ├─ DepthCopier: Float32 256x192 + UInt8 256x192 → Data (row by row)   ~250 KB, synchronous
          ├─ retain frame.capturedImage (CVPixelBuffer), NOT the ARFrame
          ├─ build FrameRecord (pose, K, sizes, exposure, tracking, thermal, paths)
          └─ FrameWriter.enqueue(job)                          returns immediately
                 │
                 └─ serial DispatchQueue (qos .utility), DispatchSemaphore(value: 2)
                      if semaphore.wait(timeout: .now()) fails → drop, stats.dropped += 1
                      else: JPEGEncoder.encode(pixelBuffer) → rgb/NNNNNN.jpg
                            write depth/NNNNNN.f32, conf/NNNNNN.u8
                            JSONLWriter.append(frames.jsonl, record)
                            signal
```

Rules:
- Never hold more than one `ARFrame`; ARKit stops delivering frames when frames are retained. Retaining `capturedImage` alone is fine.
- `KeyframePolicy` (CadastreCore): keep when `tracking == .normal` and `t − t_last ≥ min_dt` and (`‖p − p_last‖ ≥ min_translation` or `angle(R, R_last) ≥ min_rotation`). Defaults 0.1 s, 0.10 m, 5°. `.serious` thermal doubles the distance/angle thresholds.
- `JPEGEncoder`: one `CIContext(mtlDevice: MTLCreateSystemDefaultDevice()!, options: [.cacheIntermediates: false])`; `CIImage(cvPixelBuffer:)`; `context.jpegRepresentation(of:colorSpace:options: [kCGImageDestinationLossyCompressionQuality as CIImageOption: 0.85])`. Around 10 ms per frame on A17 Pro. No orientation transform (see session-format.md).
- `DepthCopier`: lock base address, read `CVPixelBufferGetBytesPerRow`, copy `width * 4` (or `width * 1`) bytes per row into a contiguous `Data`.
- `JSONLWriter` (CadastreCore): `FileHandle` opened for appending, `synchronize()` every 50 lines and on close. Encoding uses `JSONEncoder` with `outputFormatting = [.sortedKeys, .withoutEscapingSlashes]`, one object per line.
- Manifest: written with `status: incomplete` when recording starts, rewritten with stats and `status: complete` at stop. `SessionStore` repairs incomplete manifests on launch by counting files.

## 6. Stills, markers, landmarks, mesh

- **StillCapture**: `session.captureHighResolutionFrame { frame, error in … }` → on the writer queue encode `frame.capturedImage` to `stills/NNN.jpg`, record `frame.camera.intrinsics`, `frame.camera.imageResolution`, pose, exposure. Rate-limit to one in flight.
- **MarkerLogger**: on `didAdd`/`didUpdate` anchors, for each `ARImageAnchor` append `{t, i, marker_id: anchor.referenceImage.name, T_wa: anchor.transform, tracked: anchor.isTracked, physical_width_m}`. Throttle updates to 5 per second per marker.
- **LandmarkLogger**: `arView.raycast(from: point, allowing: .estimatedPlane, alignment: .any).first?.worldTransform` → position column; append record; add a small `ModelEntity` sphere at the point for feedback.
- **MeshExporter** at stop: for each `ARMeshAnchor` in `session.currentFrame?.anchors`, read `geometry.vertices` (stride/offset aware), transform by `anchor.transform`, read `geometry.faces` (UInt32 triples) and `geometry.classification` (UInt8 per face, may be nil) → append to `mesh.obj` / `mesh_classes.u8`, running on the writer queue with a progress callback for the finalizing overlay. Typical room: 50k–300k faces, 5–30 MB OBJ.

## 7. Health policy (CadastreCore)

```swift
struct HealthPolicy {
  static let minFreeToStart: Int64 = 2_000_000_000
  static let minFreeToContinue: Int64 = 500_000_000
  static let warnAfter: TimeInterval = 300
  static let stopAfter: TimeInterval = 600
  func decision(freeBytes: Int64, elapsed: TimeInterval, thermal: Thermal) -> Decision  // .ok, .warn(String), .stop(String), .thresholdMultiplier(Double)
}
```

Free space from `URL.resourceValues(forKeys: [.volumeAvailableCapacityForImportantUsageKey])`. `UIApplication.shared.isIdleTimerDisabled = true` while on the capture screen.

## 8. Persistence and files

- `Documents/projects.json`: `{projects: [{slug, name, levels: [{slug, name, index}], rooms: [{slug, name, levelSlug}], markers: [{id, note}]}]}`.
- `Documents/sessions/<project>/<session-id>/…` per `session-format.md`.
- Info.plist: `UIFileSharingEnabled = true`, `LSSupportsOpeningDocumentsInPlace = true` so the Files app, Finder and the Apple Devices app on Windows can browse and copy sessions.
- Share sheet: `SessionReviewView` can zip a session (`NSFileCoordinator` + `Compression`/`AppleArchive` is heavy; use a simple `FileManager` copy to a temp folder and `UIActivityViewController` with the folder URL, or skip zipping and rely on Files) — zip is a stretch goal, Files is the required path.

## 9. State machine (capture)

```
idle ──enter screen──▶ preview ──REC──▶ recording ──Stop──▶ finalizing ──done──▶ reviewed
                          ▲              │  ▲                  │
                          │   interruption│  │resume            └──error──▶ error (manifest repaired, files kept)
                          └──────────────┘  └── paused ──────────┘
```

`AppState.capture` publishes the state, elapsed, keyframes, dropped, free bytes, thermal, tracking, markers seen; the HUD is a pure function of it.

## 10. Testing

- CadastreCore tests (run on Linux in CI): `Transform` (compose, invert, column-major round trip, rotation angle), `KeyframePolicy` (distance, angle, dt, tracking gates, thermal multiplier), `Records` encode/decode against the exact JSON in `session-format.md` (golden strings), `JSONLWriter` (line count, fsync cadence), `HealthPolicy` decisions, `SessionID` slugs.
- Simulator build in CI catches compile errors in the ARKit layer.
- Device: the in-app Test plan per build. The owner runs `cadastre validate` on every session and pastes the summary.
- Log: `log.txt` receives every state change, ARKit error, dropped-frame count per minute, and export timings.

## 11. Known pitfalls

- `CVPixelBufferGetBytesPerRow` padding (copy rows).
- Retaining `ARFrame` objects (only retain the pixel buffer).
- `captureHighResolutionFrame` is unavailable while the session is not running or on unsupported formats; check `configuration.videoFormat.isRecommendedForHighResolutionFrameCapture` and fall back gracefully.
- `ARReferenceImage` validation failures for low-detail images: markers include a high-detail ring for this reason; keep the PNGs ≥ 1000x1000 px.
- Swift 6 strict concurrency: keep `SWIFT_VERSION = 5.0` in `project.yml`; mark ARKit delegate classes `final class … : NSObject, ARSessionDelegate` and hop to the main actor explicitly for UI state.
- Portrait-only UI with landscape-oriented `capturedImage`: never rotate the stored image; the HUD does not display the raw image, it displays `ARView`.
